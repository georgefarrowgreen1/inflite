# InFlite 4.02

Calendar, Notes and People have been rebuilt around their individual tasks. Notes offers compact date-grouped lists, a grid, a Checklists collection and a quiet editor that does not focus the keyboard when opening an existing note. People has alphabetical contact groups, readable profiles and an explicit UTF-8 vCard import with a local preview. Calendar opens on the selected week, supports a month grid and keeps event timing ahead of optional descriptions. Source dates, timed events and unscheduled rides remain distinct. Empty collections expose useful creation actions without repeated introductory panels or search/refresh clutter.

Contact imports accept at most 100 named entries from a file no larger than 512 KB. Unknown URLs, photos and commands are ignored. Unsupported encodings and control characters are rejected. The preview performs no writes; confirmation uses the same encrypted, owner-scoped record journal as manual contacts. Closed previews and replaced account lifetimes stop late reads/writes. Partial imports retain the remaining queue without recreating acknowledged entries.

The shared design system now defines palette-derived Liquid Glass materials, specular edges and depth. Floating chrome, menus and sheets can sample the backdrop; scrolling cards, charts, maps and document/message bodies retain a static readable surface. Controls use the shared semantic radii, padded text, centered glyphs, focus rings and touch targets. Motion follows the existing lifecycle and reduced-motion settings. Reduced transparency, higher contrast, unsupported filters and forced colors receive opaque or system-color fallbacks.

The pass covers Today and the persistent shell, all eight native apps, Files, launcher/search/activity/recovery, standalone app views, sign-in/account/admin and InFlite status. The personal portfolio and Pedal Revolution's fitting interface retain their own app-specific design; their existing shared token blocks are regenerated normally. Original logos, semantic chart/map colors, editor ownership, encryption, authentication and file access semantics are preserved.

Native app code, lazy editors and styles are published as an immutable release graph under `/organise/releases/4.02/`, with app entries/connectors under each app's `roof/releases/4.02/`. An older tab therefore requests its matching lazy modules and styles after a newer deployment. `tools/build-organise.mjs` copies the source graph and refuses to overwrite a different release artifact. `--draft` is only for assembling an unpublished release; never use it on a deployed graph. Future releases must retain prior graphs. The service worker only admits known static release files and only falls back to a matching build. Private responses are never cached there.

The first-open budgets remain 14 KiB gzip JavaScript and 4 KiB CSS per new app. Editing/import styles load on demand. Validation includes Chromium and WebKit app flows, responsive and keyboard geometry, real private backend records, encrypted offline recovery, conflict resolution, owner replacement, explicit import, immutable release generation, shared theme/glass preferences and existing shell/app regression suites.
