# InFlite 4.20 — app launcher

The permanent dock has six stable slots: Today, four favourites, and Apps. On first use, eligible apps are chosen from Calendar, Files, Chats and Mail, followed by available alternatives. Editing favourites is explicit; running apps and background updates do not reorder them. Unavailable saved apps retain their slot and cannot launch. Empty slots lead directly to the favourites editor. Today uses a sun glyph to distinguish it from Calendar.

Apps opens a labelled three-column library with a local app-name search. Edit selects up to four favourites. Security Module stays directly accessible; the remaining existing commands live under More from InFlite. The library retains native dialog focus trapping, Escape, outside dismissal, keyboard sizing and explicit permission checks. A stale library cannot act after closure, account release or app access revocation. The optional shell stores only validated, distinct app IDs under an account-specific device preference key; searches, names, files and app contents never enter history or storage through the launcher.

App launch geometry is captured before the library closes. The frame performs the existing route change inside a native View Transition: the app surface expands from the icon while the previous surface recedes. Returning to Apps creates the new library inside that transition and measures its actual destination icon. The dock retains its own snapshot name and remains outside page transforms. The transition does not clone app DOM, make bitmap files, animate blur, remount app modules or change draft/scroll ownership. Browsers without View Transitions use a shorter origin zoom on the existing destination. Reduced motion switches immediately. New navigation, sign-out, visibility changes and accessibility changes cancel stale motion and clean up its styles.

`F.nav.launchMotion` is an account-owned optional shell adapter, installed and removed by `createWorkspace`. Core route ownership still guards each render and the adapter's cleanup. Its origin metadata may contain a synchronous shell render callback and destination resolver; native module navigation does not forward these options. Only this synchronous callback can open the returning launcher without cancelling its own transition.

`launcher-model.js`, `launcher-motion.js` and `launcher.css` belong to the reviewed optional OS asset closure and are included in both updater and service-worker lists. Existing common-core, app, base-shell and aggregate OS budgets stay fixed. The launcher has its own bounded JS/CSS bucket. Native Calendar/Notes/People 4.10 asset graphs and app data contracts remain unchanged.

Validation covers app launch and return in Chromium and WebKit; native and fallback transitions; favourites and malformed preferences; native dialog focus; narrow, wide and landscape layouts; stable dock geometry; retained draft nodes and scroll; Files navigation; rapid route replacement; sign-out cleanup; reduced motion; API/security contracts; offline closure; and existing framework/OS budgets.
