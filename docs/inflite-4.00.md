# InFlite 4.00

Calendar, Notes and People are native singleton modules in the existing shell at `/calendar/`, `/notes/` and `/people/`. They share the verified account, persistent dock, theme, navigation, search, Files and lifecycle. Workspaces remain retired.

Calendar provides an agenda, week selector, event creation/editing, all-day dates, timezone-aware times, linked items, invitations for review and ICS exports. It combines saved events with fresh dated Fitness, reminder, Chats, Mail and Markets metadata. Suggestions and estimates are labelled. An undated ride is not assigned an invented start time. Today shows the nearest saved events. Optional panels append without shifting existing day cards.

Notes supports private plain text, checklists, autosave, explicit links and text exports. People supports private contacts, conversation links, related events/notes, email preparation and exports. File links resolve owned metadata; they do not copy bytes. Invitations and emails require review in their destination app; nothing is sent automatically.

The common feature graph lives under `today/public/organise/` and loads on demand. Editor and picker code remain lazy. Each native app has a 14 KiB gzip first-open JS ceiling and 4 KiB CSS ceiling, independently measured; the existing native app ceilings remain unchanged. The service worker accepts only an explicit list of shared static assets for these three apps. Private API responses never enter Cache Storage.

The Root proxy exposes only fixed `/api/organise/list` and `/api/organise/record` capabilities. The account service validates origin, session and captured owner before parsing bodies. Account-owned D1 records use strict typed schemas, bounded strings/checklists/links, optimistic versions and idempotent operation IDs. Changed/deleted records require review. Up to 500 retry responses are kept for at most 30 days; versions fence older retries. Record bodies are fetched individually; lists omit large text. Calendar ranges paginate chronologically. Account export streams five records at a time. Deleting an item clears its main content and retains a small versioned tombstone, so an old create cannot resurrect it. Account deletion clears records and operation responses and fences late writes.

Pending writes and unfinished manual forms use the existing encrypted, acknowledged IndexedDB journal and account lifetime. New typing cannot be cleared by an older save. Uncertain requests retry their original operation before newer edits. Offline edits survive reopening; conflicts expose both versions and an explicit save-as-copy choice. Form drafts do not become cloud events/contacts until Save is chosen. No private text is written into URLs or unencrypted local storage.

Validation covers private D1/R2 CRUD, foreign-owner/CSRF rejection, concurrency and operation reuse, real opaque Drive IDs, search/pagination, linked records, deletion, complete streamed export, all-day dates, source privacy, ICS folding, size budgets, Chromium and WebKit UI, offline recovery, conflict review, form recovery, responsive geometry and actual Root boot/navigation. The existing Root API, framework, dock and browser regression suites are also run. Live deployment checks verify versions, routes/assets, private-response behavior and release CI.

## 4.01 refinement

The three apps now have purpose-specific views. Calendar opens on a selectable month grid, with a compact week view, date navigation and a chronological agenda. Linked source dates are distinguished from all-day events; planned rides without a confirmed start read “To plan”. On desktop the calendar sits beside the agenda. Notes uses preview cards with modification dates and checklist progress, a title-led writing surface and secondary linked-item/export actions. People groups contacts alphabetically and opens saved records as profiles, with explicit editing and available communication actions. Saved events likewise open as readable details before editing.

Repeated introductory panels, permanent Refresh buttons and duplicate creation controls have been removed. Search, error recovery, counts, touch targets, focus rings, rounded surfaces and motion use shared theme tokens. Reduced motion remains supported. The encrypted journal, private API, account ownership checks and shared dock lifecycle are unchanged. Browser coverage includes populated libraries, month/week navigation, saved profiles, genuine drafts, both appearance modes and 320/390/1440 px layouts in the real shell.
